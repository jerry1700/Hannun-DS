# S15P21E105-91 · 이슈 화제성 점수 계산

| 항목 | 내용 |
|---|---|
| 상태 | 구현·실데이터 검증 완료 |
| 결과물 | `hannun.feed.scoring` — `issue_summary.hot_score` 컬럼 (피드는 이 내림차순) |
| 관련 티켓 | 90(issue_summary 에 얹음), 93(다양성 신호의 실측 근거) |

## 1. 티켓 해석

이슈 피드의 정렬 기준. "지금 무엇이 화제인가"를 규모·확산·신선도로 수치화한다.

## 2. 공식과 근거

```
hot_score = ( log2(1+기사 수) + w × log2(1+언론사 수) ) × exp(−경과시간/τ)
            w = 2.0 (언론사 다양성 가중),  τ = 24h (신선도 반감)
경과시간 = 창에서 가장 늦은 발행 시각(배치의 "지금") − 이슈의 마지막 기사 시각
```

| 선택 | 근거 |
|---|---|
| 다양성을 규모보다 무겁게 (w=2) | 실측(93): 정형 기사는 1\~3곳, 진짜 화제는 13\~17곳이 다룸 — 다양성이 "사회적 화제"를 가장 잘 가름 |
| 로그 스케일 | 시황 483건 같은 대량 덩어리가 선형으로 압도하지 못하게 |
| 지수 신선도 감쇠 (τ=24h) | 마지막 기사 이후 하루 지나면 1/e — 어제 끝난 이슈는 오늘 밀려난다 |
| 기준 시각 = 창 내 최신 발행 시각 | 배치 재실행이 결정적(실행 시각과 무관) |

값은 전부 `FeedConfig`/CLI 인자로 조정 가능 — 서비스 감각에 따른 튜닝은 BE/PM 피드백 후.

### 산출 컬럼 (`gold/issue_summary/window_start=…/issue_summary.parquet`, 티켓 90·34 포함)

| 컬럼 | 뜻 |
|---|---|
| `window_start`, `window_end` | 이 요약을 만든 창(UTC, 양끝 포함) |
| `issue_local` | 창 안의 임시 번호 — `issue_quality`·`issue_registry` 와의 조인 키 |
| `issue_id` | 서비스 이슈 ID(레지스트리 승계 결과). 레지스트리가 없으면 -1 |
| `issue_size`, `publishers` | 구성 기사 수, 언론사 수 |
| `structured` | 정형(템플릿) 이슈 여부 — `issue_quality` 값 그대로 |
| `category` | 구성 기사 카테고리(OTHER·빈값 제외)의 다수결. 동률에 대표 기사 값이 있으면 그것, 라벨 기사가 없으면 대표 기사 값(티켓 34) |
| `representative` | 대표 기사 `article_id` — 이슈 중심(centroid)에 가장 가까운 기사, 동률이면 최초 발행 |
| `first_published_at`, `last_published_at` | 구성 기사의 최초·최종 발행 시각(UTC) |
| `hot_score` | 위 공식. 피드는 이 내림차순 |
| `summarized_at` | 요약 시각(UTC) |
