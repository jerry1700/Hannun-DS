# S15P21E105-90 · 대표 기사 선정 (이슈 피드)

| 항목 | 내용 |
|---|---|
| 상태 | 구현·실데이터 검증 완료 |
| 결과물 | `src/hannun/feed/` (store·pipeline·cli), CLI `hannun-feed`, `issue_summary/` 테이블 |
| 관련 티켓 | 93(issue_quality 가 입력), 97(issue_id 조인), 91(화제성 점수 — 같은 테이블에 추가 예정) |

## 1. 티켓 해석

이슈 피드 카드의 얼굴이 될 대표 기사를 이슈마다 하나 뽑는다. 함께 피드에 필요한
요약 지표(규모·언론사 수·시간 범위·정형 여부·서비스 issue_id)를 이슈 단위 테이블
`issue_summary/` (창 단위 파티션)로 만든다 — BE 는 이 테이블 하나로 피드를 그린다.

## 2. 선정 규칙 — 실측 비교로 결정

후보: ① 최초 발행 기사 ② 이슈 중심(centroid) 최근접 기사.
1/2 창 상위 12개 이슈에서 나란히 비교(눈검사):

| 이슈 | 최초 발행 | 중심 최근접 |
|---|---|---|
| 날씨(69건) | "세계의 날씨(1월2일)" | "[출근길 날씨] 오늘도 추위 계속…" |
| 봉하 회동(38건) | 김경수 마주침 프리뷰 기사 | 회동 본건("이재명 만난 文…") |
| UFO 소동(30건) | 지질자원연 조직 신설(곁가지) | "전국 UFO 대소동…발사장면 공개" |

**중심 최근접 채택** — 최초 발행은 프리뷰·곁가지가 이슈의 얼굴이 되는 사례가 반복됨.
동률이면 최초 발행이 이긴다. 발행 시각 정보는 버리지 않고
`first_published_at`/`last_published_at` 컬럼으로 보존(피드의 신선도 표시·화제성
계산(91)에 쓰임).

## 3. 구조

```
issue_quality(93 최종 배정) + embedding(중심 계산) + issue_registry(97 issue_id)
  + gold(발행 시각)
  → 이슈별: 대표 기사(중심 최근접), 규모, 언론사 수, 시간 범위, structured
  → issue_summary/window_start=…/ (이슈 단위, 창 파티션)
운영 순서: cluster → succeed → quality → feed
```

- 레지스트리가 없으면 issue_id=-1 로 두고 경고 — 요약 자체는 유효(개발 편의)
- 노이즈(-1)는 요약에서 제외 — 단독 기사 노출 정책은 PM 미결

## 4. 검증

- 테스트 4개(중심 최근접 vs 최초 발행·issue_id 조인·정형 플래그·노이즈 제외·레지스트리
  부재) — 전체 281개 통과
- 실데이터 1/2 창: 이슈 509개 요약, 전부 issue_id 부여. 상위 이슈 대표가 피드처럼
  읽힘("전장연, 지하철 탑승 놓고 11시간째 대치" 75건/16곳 등). 봉하 이슈 38건은
  구제 3건 반영이 흘러들어온 것 — 93→90 파이프라인 정합 확인
