## 1. 티켓 해석

DS2 가 만든 변환기(`scripts/export_ds2_jsonl.py`, 121)는 완성돼 있었지만 **아무도
부르지 않았다** — 일일 체인에도, DAG 에도 없고 컨테이너에 출력 마운트도 없어
`~/ds_output` 이 영구히 비고, DE 의 gold_issue_feed 는 관점 값을 NULL 로 채웠다
(09-10 저장소 전체 점검에서 발견). 이 티켓은 그 끊긴 자동화를 잇는다: 체인이 매일
피드 산출 직후 같은 창으로 변환기를 돌려 `~/ds_output/<실행일>.jsonl` 을 만든다.

## 2. 결정

| 결정 | 이유 |
|---|---|
| 체인 9단계째로 추가 (feed 직후) | 창(START/END)을 이미 아는 곳이 창 정합을 보장 — "창 섞으면 매칭 48%, 맞추면 99%"(DE 실측) 문제의 해소 지점 |
| 파일명 = 실행일(KST) 하나 | DE 계약("하루 파일, clusteredAt 늦은 것 우선")과 부합. 재실행은 같은 파일 원자 교체 |
| `--overwrite` 옵션 신설 | 기존 FileExistsError 가드는 보존(기본값) — Airflow 재시도·일일 재실행만 명시적으로 덮어쓴다. 임시 파일→replace 라 교체는 원자적 |
| gold-root·output-root 를 체인이 명시 전달 | 스크립트 기본값(`/home/ubuntu/...`)과 컨테이너 경로(`/data/...`) 불일치를 호출부에서 해소 — DS2 스크립트 수정 최소화 |
| `.dockerignore` 예외로 스크립트만 반입 | `scripts/*.py` 차단 원칙 유지, 이 파일 하나만 `!` 예외 |

## 3. 검증 (2023-01-02 창, 로컬)

- 실행: 이슈 509 → **502 내보냄**(7건은 분석 대상 기사 없음), 기사 3,965행,
  camelCase 필드·KST clusteredAt 확인
- 재실행 가드: 플래그 없이 재실행 → FileExistsError (기존 동작 보존)
- `--overwrite` 재실행: 성공, 같은 결과로 원자 교체
- `bash -n`·flake8 통과. 전체 테스트 무변(스크립트·설정만 변경)

## 4. 알려진 한계 (이 티켓 밖)

- `viewpointGroupLabel` 은 여전히 null — 120/30(관점 그룹 라벨) 전까지 BE 필수
  필드가 비므로 **발행(publish_clustering) 연결은 그 뒤에** 가능

  스크립트(문장 join)라 **여기서 배열로 바꾸는 게 최소 수정**일 수 있음. BE·DE 와
  계약 확정 후 별도 처리 (전체 점검 치명 1번)
- empty_briefings 172/502(34%) — DS2 fact_summary 가 빈 이슈 비율, DS2 에 공유
- 이슈 멤버십 기준: 이 스크립트는 quality(구제 후·정형 제외), DE gold_issue_feed 는
  registry(구제 전) — 통일 협의 별도 (quality 기준 제안 예정)
