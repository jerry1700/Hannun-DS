## 1. 티켓 해석

매시 :05 재군집이 UMAP 을 처음부터 다시 학습해 5차원 지도가 매번 미세하게 재배열되고,
경계의 이슈가 쪼개졌다 붙었다 한다. 운영 실측(9/15\~17, 이슈 \~700개)은 재군집마다
`created 134 / splits 78 / retired 144` — 시간마다 이슈 130여 개가 사라지고 130여 개가 새
ID 로 다시 생긴다. 승계(97)는 과반 겹침이면 ID 를 잇지만, 구성원이 실제로 갈리면 이을 수
없다. 15분 배정은 기존 이슈를 건드리지 않아 출렁임이 0 이니, 문제는 재군집 시각에 한정된다.
FE 에서 열어 둔 이슈 카드가 사라지거나 무한스크롤 커서가 어긋나는 것이 사용자에게 보이는 결함.

## 2. 설계 실측 — 로컬 1/1\~1/2 창(7,853건) 3시간 간격 7단계 시뮬레이션

실제 `cluster()`·`succeed()` 로 승계 통계를 찍었다. (A) 는 운영 수치(134/78/144)를 재현한다.

| 변형 | created / retired / splits (단계당) | 하루 끝 구제 뒤 노이즈 | (A) 이슈 673 중 절반 이상 노이즈로 잃은 것 |
|---|---|---|---|
| (A) 매 단계 재학습 (지금) | 130 / 96 / 67 | 1,226 (16%) | — |
| (B) 지도 고정 + transform | **32 / 16 / 13** | 1,936 (25%) | **155 (23%)** |
| (B′) B + transform 에포크 500 | 36 / 19 / 15 | 1,951 | 148 |
| (C) 따뜻한 재학습 — 이전 좌표를 init 으로 | 137 / 103 / 70 | — | — |
| (D) B + 노이즈 병합군집 0.80 | 41 / 15 / 14 | 1,738 | 121 |
| (D) 0.75 | 45 / 15 / 14 | 1,650 | 114 |
| **(D) 0.70** | **51 / 17 / 16** | **1,506 (19%)** | **100 (15%)** |
| (E) B + 노이즈 부분집합 UMAP+HDBSCAN | 95 / 55 / 39 | 638 | 23 |

읽는 법:
- (B) 지도를 고정하면 출렁임은 4\~6배 준다. 그러나 transform 은 새 점을 학습 점 이웃 옆에
  놓으므로, 지도 학습 뒤 터진 사건의 기사들은 서로 가까워야 할 학습 이웃이 없어 흩어진다 —
  새 이슈를 어떤 transform 으로도 못 잡고(B′ 도 같음) 구제(0.85)로도 못 되찾는다.
- (C) 초기 배치를 이전 좌표로 줘도 500 에포크 최적화가 배치를 사실상 다시 그린다. 출렁임은
  초기값 문제가 아니라 이웃 그래프 변화 + HDBSCAN 경계 민감도다.
- (D) 1단계 노이즈에서 기존 이슈 중심 곁(0.85)은 구제 몫으로 남기고, 나머지를 원래 384차원
  코사인 평균 연결로 묶어 3건 이상이면 새 이슈. UMAP 이 없어 점이 늘어도 기존 병합이 뒤집히지
  않는다. 문턱을 0.80 → 0.70 으로 내려도 새 이슈의 순도(재학습 기준 같은 이슈 비율)는 0.81 로
  같았고 잃는 이슈만 121 → 100 으로 줄었다. 골드셋(104)에서 코사인 0.75 이상인데 기계가 갈라
  둔 쌍의 76%를 사람이 같은 이슈로 봤으니 0.70 은 그 경계 안쪽이다.
- (E) 는 재학습이 이슈를 찾는 방식 그대로를 노이즈 2천 점에만 적용한 것 — 잃는 이슈는 거의
  없지만 출렁임의 3분의 2가 돌아온다(새 이슈 사이에서 부분집합 UMAP 이 매시 재배열). 순도 0.77.

## 3. 결정

| 결정 | 이유 |
|---|---|
| 창(window_start)마다 지도 한 번, 기사별 좌표를 표로 저장 | 학습 점을 다시 transform 하면 학습 좌표와 다른 자리(최대 0.8)가 나온다 — 좌표를 저장해야 진짜 고정. 지도 객체는 pickle(3천 점 6MB), transform 은 결정적 |
| 2단계 = (D) 코사인 평균 연결, 문턱 0.70 (`new_issue_sim`) | 출렁임 2.5\~6배 감소와 새 이슈 손실 15% 의 교환점. 문턱은 설정값 — EC2 골드셋으로 재확인 |
| 기존 이슈 중심 0.85 이내는 2단계에서 뺀다 (`near_issue_sim`) | 그 점들은 후속 기사라 뒤의 품질 구제가 붙인다. 2단계가 먹으면 같은 이슈가 둘로 갈린다 |
| 설정(차원·이웃·seed·임베딩 모델)이 다르면 재학습 | 서명 캐시(123)와 같은 원칙 — 조용히 틀린 좌표를 쓰지 않는다 |
| 배정 모드(MODE=assign)는 그대로 | 이슈 표에 새 기사만 붙이는 방식이 이미 고정 지도와 같은 성질 |
| 창이 미끄러지는 첫 재군집(09:05 KST)에 새 지도 | 그때 한 번은 종전과 같은 출렁임 — 하루 24회에서 1회로 |
| `--no-map` 으로 옛 경로 유지, `--refit-map` 으로 강제 재학습 | 실험·백필용. 체인은 기본값(고정 지도) |

## 4. 구조

```
cluster(map_store=MapStore)
  좌표 = MapStore.coordinates(window_start, article_ids, 벡터, 설정, 모델, fit)
           지도 없음/설정 다름/refit → fit(UMAP) → embedding_ 을 저장 (transformed=false)
           지도 있음 → 좌표 없는 기사만 reducer.transform → 표에 덧붙임 (transformed=true)
  labels = HDBSCAN(좌표)                                  ← 1단계, 기존 이슈는 흔들리지 않는다
  labels = attach_new_issues(벡터, labels)                 ← 2단계, 노이즈에서 새 이슈
             노이즈 − 기존 이슈 중심 0.85 이내 → 코사인 평균 연결 0.70 → 3건 이상이면 새 번호
succeed → quality(구제 0.85) → feed → export
```

산출 컬럼 (`gold/umap_map/window_start=…/`)

| 파일·컬럼 | 뜻 |
|---|---|
| `reducer.pkl` | 학습된 UMAP 객체. 새 기사 transform 에 쓴다 |
| `points.parquet` — `article_id`, `point`(umap_dims 개), `transformed` | 기사별 고정 좌표. transformed 는 학습 점(false)/뒤에 얹힌 점(true) |
| `meta.json` | umap_dims·umap_neighbors·seed·model·fitted_at·n_fitted — 유효 조건 |

`ClusterStats` 에 `map_fitted`·`map_transformed`·`new_issues` 추가 — 체인 로그에서 매시
학습 여부와 2단계가 만든 이슈 수가 보인다. `issue_centroids`·`nearest_issue_assignments` 는
품질·배정·새 이슈 탐지가 같이 쓰게 되어 `clustering/centroids.py` 로 옮겼다(quality 가 import).
