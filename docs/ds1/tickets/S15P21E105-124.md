## 1. 티켓 해석

MVP 코드가 다 나온 시점에 CODE_STYLE.md 를 기준으로 DS1 이 쓴 파일 전부를 한 번에
검수한다. 기준은 문서 첫 줄 그대로 "누가 어느 날 짰는지 티 나지 않게". 지적 123건을
P0(동작·안전) / P1(규칙 위반) / P2(취향) 로 나눠 전부 고쳤다. DS2 소유 파일
(`scripts/export_ds2_jsonl.py`)은 내가 덧붙인 부분만 봤고 그 파일의 관례는 따랐다.

## 2. 동작이 바뀐 것 (P0)

| 항목 | 내용 |

## 3. 규칙 위반 (P1·P2)

- 이름: `result`·`data`·`obj`·`q`·`g`·`d`·`st` 15곳 → `upserted`·`record`·`parsed`·`found`·`grouped`·`verified`·`placements`·`quality_table`·`gold_table`·`stats`
- 실측 수치가 든 주석·docstring·CLI help 20여 곳 → '왜'만 남기고 `(티켓 N)` 포인터. 수치는 원래 있던 티켓(10·93·97·102·104·123)에 이미 있다. CLI help 기본값은 설정 dataclass 에서 f-string
- 반환 타입 4곳, docstring 안 볼드·목록·`Args:` 꼴, 컬럼마다 붙은 설명 주석(dedup·issue_quality·issue_registry·issue_summary 스키마 → 클래스 docstring 한 문단 + 티켓의 산출 컬럼 표), 길이 제각각 구분선, 한글 예외 메시지 2곳, 루프 안 INFO → DEBUG, 함수-클래스 순서(`text_sha1`·`majority_category`·테스트 헬퍼), `__init__.py` docstring 7개, 이모지 1, "일일 배치" stale 표현(셸·Dockerfile·DAG), 3중 되풀이 주석(succession)
- 스크립트: `sys.path` 조작·로직 복사 제거 — 골드셋 채점 공용 함수를 `hannun/quality/goldenset.py` 로(`load_pairs`·`load_labels`·`consensus_components`·`labeler_agreement`·`score_pairs`·`representative_of`), `compare_embeddings` 는 운영 인코더(`EncoderConfig`·`build_input`·`encode_texts`)를 그대로 쓴다, `profile_dataset` 은 규칙 모듈의 `BROKEN_ENTITY` 를 import. main 안 import 는 상단으로. 채점 결과 키를 영어로(`same_issue_predicted.precision`·`boundary.oversplit_rate`·`recall_in_sample`)
- 테스트: 여러 사실을 한 테스트에 묶은 14건 분리, 공통 기사 JSONL 생성은 `conftest.article_jsonl` fixture 로(테스트 파일 간 import 제거), `test_gold` ↔ `test_ingest` 분리, `majority_category` 규칙은 parametrize, 골드셋 모듈 테스트 7개 신규

## 7. CODE_STYLE 보강

검수하며 규칙이 없어 판단이 흔들린 것을 문서에 더했다: `__init__.py` docstring 필수,
모듈 docstring 첫 줄 한 문장, docstring·주석의 마크다운 금지, 실측 수치는 티켓으로
보내고 `티켓 N` 표기 통일, CLI help 기본값 f-string, 스크립트 import 상단, 테스트 공용
입력은 conftest fixture, 저장 형식 변경 시 옛 파티션 처리.
