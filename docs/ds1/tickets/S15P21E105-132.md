# S15P21E105-132 · 저장 원자성 — UMAP 지도 세대·Gold 교체 파티션·체인 완료 마커

| 항목 | 내용 |
|---|---|
| 상태 | 구현·테스트 완료 — 머지 후 EC2 재빌드. 열려 있는 창의 옛 배치 지도는 다음 창 전환(재학습)까지 그대로 읽힌다 |
| 결과물 | `MapStore` 세대 디렉터리(`gen=…`)와 `current` 포인터, `GoldStore.upsert` 의 저장소 전체 article_id 조회, `run_daily_chain.sh` 의 `ds_output/_chain_status.json` |
| 관련 티켓 | 128(고정 지도 — 세 파일 배치의 원작), 10·91(Gold 파티션·멱등 규칙), 118(DE 가 최근 3일을 매번 다시 내려줌), 122(ds_output 내보내기), 131(같은 리뷰의 High 항목) |

## 1. 티켓 해석

코드 리뷰(2026-09-22)의 Medium 세 항목. 셋 다 "쓰다가 죽거나 입력이 이동했을 때 저장소가
조용히 일관성을 잃는" 문제라 한 티켓으로 묶었다.

| 결함 | 어디서 | 결과 |
|---|---|---|
| 지도 세 파일이 따로 교체된다 | `MapStore._write` — reducer 는 tmp+replace, points·meta 는 그 뒤에 각각 | 셋 중 하나만 바뀐 채 죽으면 새 reducer 에 옛 좌표 표(또는 반대). 다른 공간의 좌표가 한 행렬에 섞여 군집이 조용히 틀어진다 |
| Gold replace 가 같은 날짜 파티션만 본다 | `GoldStore.upsert` | 재크롤링이 발행 시각(=파티션)을 고치면 옛 파티션 행이 남아 한 article_id 가 두 줄. 정제·임베딩·군집 조인이 둘을 받는다 |
| 체인이 끝났다는 표시가 없다 | `run_daily_chain.sh` 는 로그 한 줄 `[chain] done` | 하류(DE gold_issue_feed)와 운영자는 ds_output 파일의 mtime 만으로 체인이 끝까지 갔는지 중간에 죽었는지 모른다 |

일어날 확률은 낮지만(지도 학습은 창당 1회, 09:05 KST 재군집 안의 몇 초) 셋 다 실패가 로그에
남지 않는 종류다. 정합성이 깨진 뒤 발견은 이슈 품질의 이상으로만 드러난다.

## 2. 결정

| 결정 | 이유 |
|---|---|
| 지도 = 세대 디렉터리 `gen=<UTC 시각>/{reducer.pkl, points.parquet, meta.json}` + `current` 한 줄 포인터 | 세 파일을 다 쓴 뒤 포인터 파일만 `os.replace` 로 바꾼다. 쓰다 죽으면 포인터는 옛 세대를 가리키고, 미완성 디렉터리는 다음 재학습이 지운다. 활성 세대는 세 파일이 다 있어야 인정 — 포인터가 가리키는 디렉터리가 없거나 비었으면 지도 없음으로 보고 다시 학습한다 |
| 옛 배치(세 파일이 창 디렉터리에 바로 있음)도 그대로 읽는다 | 배포 직후 열려 있는 창의 지도를 버리면 그 시각 재군집이 재학습이 되어 created/retired 가 한 번 튄다(128 §7 의 창 전환 수치). 다음 창 전환에 새 배치로 넘어가며 옛 파일은 그때 지운다 |
| transform 점 덧붙이기(`_append`)는 세대 안 `points.parquet` 한 파일 tmp+replace | 좌표 표 하나만 바뀌므로 파일 단위 원자성으로 충분하다 |
| `meta.json` 에 `generation` 을 기록 | 어느 세대의 설정인지 파일만으로 맞춰볼 수 있게 |
| Gold upsert 가 저장소 전체에서 article_id 를 찾는다(`_locate`, article_id 컬럼만) | keep 은 다른 날짜에 있어도 건너뛰고(`skipped_existing`), replace 는 옛 날짜의 행을 지운 뒤 새 날짜에 쓴다(`replaced`). 파티션 수만큼 컬럼 하나 읽기라 30일 3만 행이면 수십 ms — 매 적재에 붙여도 된다 |
| 완료 마커 `ds_output/_chain_status.json`, tmp 에 쓰고 mv | 담는 것: run_id·status(ok/failed)·mode·창·started_at/finished_at·output(그날 JSONL 경로)·단계별 seconds/rc. EXIT trap 으로 실패해도 남는다(status failed, steps 의 마지막 rc 가 멈춘 단계). 스크립트 종료 코드는 그대로라 Airflow 의 실패 감지는 바뀌지 않는다. ds_output 에 두는 이유: DE 가 읽는 경계가 거기다 |
| `step` 이 실패 단계도 로그·마커에 남긴다(`"$@" && rc=0 \|\| rc=$?`) | 종전에는 `set -e` 가 함수 안에서 셸을 바로 끝내 실패한 단계의 `step X …s rc=` 줄이 안 찍혔다. `\|\|` 폴백(assign → cluster)의 동작은 그대로 |

## 3. 저장 배치 변경

```
gold/umap_map/window_start=YYYY-MM-DD/
  current                           ← "gen=20260923T000512123456" 한 줄
  gen=20260923T000512123456/
    reducer.pkl
    points.parquet                  ← 컬럼은 128 과 같음(article_id·point·transformed)
    meta.json                       ← 128 의 키 + generation
```

```
ds_output/_chain_status.json
{"run_id": "20260922T000512Z", "status": "ok", "mode": "recluster",
 "window_start": "2026-09-21", "window_end": "2026-09-22",
 "started_at": "2026-09-22T00:05:12Z", "finished_at": "2026-09-22T00:12:40Z",
 "output": "/home/ubuntu/ds_output/2026-09-22.jsonl",
 "steps": [{"step": "preprocess", "seconds": 31, "rc": 0}, …, {"step": "export", "seconds": 132, "rc": 0}]}
```

Gold 파티션 배치는 그대로. 바뀐 것은 한 article_id 가 저장소 전체에서 한 줄이라는 보장이다.

## 4. DE 에 전달할 읽기 규칙 (협의 문구)

> ds_output 에 `_chain_status.json` 이 생깁니다. 체인이 끝날 때마다(성공·실패 모두) 다시 씁니다.
> 1. `status` 가 `ok` 이고 `finished_at` 이 마지막으로 병합한 것보다 새로울 때만 `<날짜>.jsonl` 을 읽어 주세요. `run_id` 를 기억해 두면 같은 결과를 두 번 병합하지 않습니다.
> 2. `status` 가 `failed` 면 그 실행은 산출을 갱신하지 못했습니다. 직전 파일을 그대로 두고 경고만 남겨 주세요. `steps` 의 마지막 항목이 멈춘 단계입니다.
> 3. 마커는 `.json` 이라 `*.jsonl` 패턴에는 걸리지 않습니다. 디렉터리 전체를 보내는 경로가 있으면 이 파일은 빼 주세요.

## 5. 검증

- 테스트 +6, 전체 402 통과(DS2 모델 테스트 제외), flake8 통과.
  - 지도 4: 재학습이 새 세대로 포인터를 옮기고 옛 세대를 지운다 / 반쪽만 쓰인 세대는 포인터가 옮겨지기 전까지 무시되고 다음 재학습이 치운다 / 포인터가 가리키는 세대가 없으면 재학습 / 옛 배치를 그대로 읽고 재학습 때 새 배치로 바꾼다.
  - Gold 2: replace 가 발행일이 바뀐 기사를 옛 파티션에서 빼고 새 파티션에 쓴다(article_id 유일) / keep 이 다른 파티션에 있는 기사를 건너뛴다.
- 체인 스크립트는 가짜 인터프리터로 3종 실행: 정상(status ok, 8단계 기록), dedup 실패(종료 코드 3 전파, status failed, steps 가 dedup rc 3 에서 끝남), assign 폴백(assign rc 3 뒤 cluster 0, status ok).
- 배포 뒤 확인: 첫 재군집은 옛 배치 지도를 읽어 `map_fitted false` 여야 한다. 다음 창 전환(09:05 KST) 뒤
  `ls ~/gold/umap_map/window_start=<오늘>/` 에 `current` 와 `gen=…` 하나. `cat ~/ds_output/_chain_status.json` 의 status ok, steps 8개.
