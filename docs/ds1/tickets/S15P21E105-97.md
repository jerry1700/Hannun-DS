# S15P21E105-97 · 재군집 후 이슈 ID 유지 (승계)

| 항목 | 내용 |
|---|---|
| 상태 | 완료 + 운영 실전 검증(09-10, §4.5) + **자기-승계 구현 (09-11, §4.6 — 재오픈 건)** |
| 결과물 | `hannun.clustering.succession`·`registry`, CLI `hannun-succeed`, `issue_registry/` 테이블 |
| 관련 티켓 | 89(재군집이 입력), 102(운영 루프), 93(판정은 승계와 독립) |

## 1. 티켓 해석

재군집마다 HDBSCAN 번호(issue_local)는 리셋된다. 그런데 BE API 는 issueId 커서로
페이지네이션하므로 ID 가 흔들리면 무한스크롤·공유 링크가 깨진다 — **알고리즘 번호와
서비스 이슈 ID 를 분리**하고, 재군집을 넘어 ID 를 잇는 승계가 MVP 필수.

핵심 아이디어: 클러스터 번호는 매번 바뀌지만 **기사(article_id)는 불변**이다.
새 군집의 구성원이 직전 창에서 어느 이슈에 있었는지 득표로 세어 ID 를 잇는다.

## 2. 설계 실측 — 6개 슬라이딩 창 시뮬레이션 (1/1\~1/7)

48h 창을 하루씩 밀며 6번 군집화하고 승계 규칙을 적용 (`local/exp_succession.py`):

| 지표 | 값 |
|---|---|
| 창당 승계율 | 새 창 이슈의 42\~50% (마지막 창 64%) — 이슈 수명 분포(하루 내 절반 종료)와 부합 |
| 문턱 민감도 | 겹침 비율 0.3 ↔ 0.5 차이 3%p — 둔감, **과반(0.5) + 최소 2건** 채택 |
| 분열 | 창당 이슈의 \~7% — 최다 득표 군집이 ID 승계, 나머지는 새 ID |
| 병합 신호 | 창당 \~4% — 승계는 최다 득표 직전 이슈 기준(큰 쪽 생존) |
| 추적 확인 | "드론사령부" 이슈가 4개 창(나흘) 연속 한 ID 유지. 무인기 정국이 여러 ID 로 나뉘는 것은 국면 분리(가이드 "같은 국면 통합" 기준과 정합) |

## 3. 구조

```
재군집(hannun-cluster) 직후:
  새 군집 구성원 × 직전 창 레지스트리(article_id → issue_id) 득표
  → 최다 득표가 과반 & 2건 이상 → 그 issue_id 승계 / 아니면 새 ID 발급(단조 증가)
  → issue_registry/window_start=…/ 에 기사 단위로 기록
운영 루프: cluster → succeed → quality → (15분: assign → quality)
```

- **레지스트리를 기사 단위로 저장하는 이유**: 슬라이딩 창이 issue 파티션을 덮어쓰므로
  직전 창의 라벨은 issue 테이블에서 사라진다. 레지스트리가 창 단위 파티션으로 이력을
  보존하니 승계가 직전 창 issue 테이블 없이 동작하고, BE 가 쓸
  (article_id → issue_id) 뷰가 그대로 나온다
- 재실행 멱등: 새 ID 채번이 "현재 창을 제외한 최대 ID + 1" 에서 시작
- 재점화 한계(문서화): 이슈가 창 길이보다 오래 조용했다 다시 불붙으면 겹치는 기사가
  없어 새 ID — 키워드 기반 연결은 향후 과제

창이 처음으로 전진한 날(9/8\~9/9, prev 9/7)의 실측 — 시뮬레이션 예측과 일치:

| 지표 | 실측 | 시뮬레이션 예측 |
|---|---|---|
| 승계율 | **297/703 = 42.2%** | 42\~50% |
| 분열 | 36건 (이슈의 5.1%) | \~7% |
| 신규 발급 | 406 | — |

전날 inherited=0 은 같은 창 재실행(§5 자기-승계 항목)이라 규명대로.

### 4.6 자기-승계 (2026-09-11 구현 — 15분 재군집의 관문)

같은 창 재실행이 ID 를 전부 재발급하던 문제(§5 백로그, 09-09 운영 발견)를 해소.
DE 가 ds_input 15분 내려주기(118)를 깔고 "이슈 번호가 매번 재배정돼 자주 못
돌린다"고 명시한 뒤라, 이게 팀 실시간화의 마지막 관문이었다.

| 결정 | 이유 |
|---|---|
| 승계원 = 직전 창 ∪ **같은 창의 직전 실행**(우선) | 기사가 양쪽에 있으면 현재 창 배정이 최신 진실 |
| status 는 자기-승계 시 이전 값 유지 | "직전 창 대비 계보" 의미 보존 — 이 창에서 태어난 이슈는 재실행 뒤에도 new (BE 통계 안정) |
| 채번 = 전 창 통틀어 max+1 (현재 창 제외 폐기) | 옛 방식은 재실행에서 죽은 이슈의 ID 가 다른 군집에 재사용될 위험. 멱등은 이제 자기-승계가 책임 |

검증: 테스트 6개(신규 1 — 라벨 리셋+데이터 증가+새 이슈 혼합 재실행, 총 313 통과),
실데이터(1/2 창 이슈 509·기사 4,601) 재실행 — **inherited 509/509, ID 유지 100%,
신규 발급 0**. 구현 전 같은 재실행은 전량 재발급이었다.
