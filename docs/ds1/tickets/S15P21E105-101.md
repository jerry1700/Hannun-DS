# S15P21E105-101 · 모듈 패키징·실행 스크립트·문서

| 항목 | 내용 |
|---|---|
| 상태 | 일일 배치 스크립트·런북 완성. EC2 첫 스모크 대기 |
| 결과물 | `scripts/run_daily_chain.sh`, [EC2_RUNBOOK.md](../EC2_RUNBOOK.md), `.gitattributes`(sh=LF) |
| 관련 티켓 | 118(DE ds_input 계약), 89·97·93·90·91(체인 구성 단계), 102(15분 루프는 보류) |

## 1. 티켓 해석

지금까지 만든 8단계 모듈을 EC2 에서 실수집 데이터로 돌리는 실행 단위로 묶는다.
입력 계약(S15P21E105-118): `~/ds_input/<YYYY>/<YYYY-MM-DD>.jsonl`(하루 한 파일),
매일 04:00 KST 갱신, **최근 3일 매일 재작성**(늦게 오는 기사). 스크립트는 전환기를
대비해 구 구조(`<날짜>/articles*.jsonl`)도 읽는다.

## 2. 구조 — 일일 배치 하나로 시작

```
run_daily_chain.sh (cron 04:30 KST)
  ingest(최근 3일 재적재, 멱등 keep) → preprocess → dedup(48h 창) → embed
  → cluster → succeed → quality → feed
```

| 결정 | 이유 |
|---|---|
| 15분 배정 루프는 보류 | ds_input 이 일 단위 — DE 가 15분 내려주기를 제공하면 붙인다(102 의 assign 은 준비돼 있음) |
| 최근 3일 재적재 | DE 재작성 주기와 동일. ingest 가 article_id 멱등이라 중복 적재 안전 |
| 창 = 오늘·어제(UTC) 48h | 설계값 그대로. `START`/`END` 환경변수로 백필 가능 |
| 스크립트는 환경변수 주입 | GOLD_ROOT·DS_INPUT·HANNUN_PY — 로컬/EC2 어디서든 같은 파일 |
| `.gitattributes` 로 sh=LF | Windows 체크아웃 CRLF 가 EC2 bash 를 깨뜨리는 사고 방지 |
| cron 에 flock 권고 | 멱등이어도 동시 기동은 금지(TS-012 교훈) |

## 3. 검증

- `bash -n` 문법·날짜 계산(UTC 창, KST 입력 폴더) 확인
- 체인 8개 모듈 CLI 전부 `--help` 임포트 확인 — 이 과정에서 help 문구의 em dash 가
  Windows cp949 콘솔에서 UnicodeEncodeError 를 내는 것을 발견해 세 CLI 수정
- 각 단계는 실데이터(1월 창)로 이미 개별 검증됨 — 통합 스모크는 EC2 첫 실행(런북 §2)
