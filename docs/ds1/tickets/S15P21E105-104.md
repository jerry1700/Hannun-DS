# S15P21E105-104 · Golden Set 채점 스크립트·기준값 조정 실험

| 항목 | 내용 |
|---|---|
| 상태 | 채점 스크립트·시트 생성기 완성(파일럿으로 검증). 본 채점은 라벨링 주간 뒤 |
| 결과물 | `scripts/score_goldenset_clusters.py`·`score_goldenset_dedup.py`·`make_goldenset_sheets.py` |
| 관련 티켓 | 103(라벨 가이드), 10(dedup recall 미측정), 89·93(군집·문턱이 채점 대상) |

## 1. 티켓 해석

골드셋 = 사람이 만든 정답지. 파이프라인 출력(학생 답안)과 비교해 점수를 내고,
그 점수로 문턱값들(구제·배정 0.85, min_cluster_size 등)을 조정한다. 채점 과목 둘:

1. **군집**: 사람이 기사를 이슈로 묶은 라벨 vs issue_quality 배정 — **ARI**
2. **중복**: 사람이 기사 쌍을 O/X 판정 vs dedup 같은-그룹 여부 — **precision·recall**
   (precision 은 280쌍으로 쟀고 **recall 이 이번 목표**)

## 2. 스크립트

| 스크립트 | 하는 일 |
|---|---|
| `make_goldenset_sheets.py` | 라벨링 시트 생성 3종. ① **군집 쌍 시트(기본)** — "같은 이슈인가 O/X" 400쌍(같은이슈 예측 2 : 경계 1 : 무작위 1, 층 정보는 숨기고 순서 섞음) ② 중복 쌍 시트 — 유사도 상위인데 dedup 이 안 접은 쌍(recall 후보) ③ 군집 통시트(선택) — 시간대 슬라이스 표본을 유사 기사 이웃 정렬로. 제목 포함이라 산출물은 local/ 전용 |
| `score_goldenset_issue_pairs.py` | **군집 쌍 채점(기본)** — 층을 파이프라인 상태로 재유도해 묶음 정밀도·과분리율·표본 내 동거 재현율 |
| `score_goldenset_clusters.py` | 통시트 채점(선택) — 쌍 득표 과반 합의 → ARI + 라벨러 간 일치도 |
| `score_goldenset_dedup.py` | 중복 쌍 라벨 → tp/fn/fp/tn, precision·recall·F1 |

**쌍 판정을 기본으로 하는 이유**: 통시트는 5명 × 300건 = 1,500회의 무거운 판단(전체
맥락 필요)이고, 쌍 판정은 총 400회의 가벼운 판단(쌍당 10초)을 분담한다 — 인당
15~20분. 전역 구조(ARI) 증거는 파일럿 30건이 이미 담당. 층 정보를 시트에 숨기는
이유: 라벨러가 "이건 기계가 묶은 쌍"임을 알면 판정이 끌려간다.

## 3. 검증

- **군집 채점기 ↔ 파일럿 재현**: 30건을 전체 파이프라인(e5→UMAP→HDBSCAN)으로 돌려
  채점 → **ARI 0.8495** (티켓 89 의 0.850 재현). 라벨러 간 일치도 0.878
- **중복 채점기**: 자명한 쌍(접힌 쌍 10 = O, 무작위 10 = X)으로 precision/recall 1.0 확인
  — 이 스모크가 pandas NaN 버그(결측 duplicate_of 의 `is None` 검사 뚫림)를 잡아냄
- **시트 생성기**: 1/2 창 스모크. recall 후보 상위가 유사도 1.0인데 안 접힌 쌍들 =
  **min_fold_len(본문 100자 미만) 게이트로 의도적으로 안 접은 기사들**(영상·알림 류) —
  라벨링 주간에 사람이 판정할 정확한 지점

## 4. 라벨링 주간 운영 (팀 안내)

1. 표본 날짜 확정(실버 수집분 권장 — 서비스 분포와 동일) → 시트 생성해 배포
2. **군집 쌍 시트(issue_pairs, 400쌍)**: "같은 이슈인가" O/X — 분담(인당 80쌍, 15~20분),
   판정 기준은 [LABEL_GUIDE.md](LABEL_GUIDE.md) ("같은 국면 통합")
3. **중복 쌍 시트(dedup_pairs, 300쌍)**: "같은 기사인가" O/X — 분담(인당 60쌍)
4. 제출본으로 채점 → 문턱 조정 실험(창 크기·min_cluster_size·0.85들)
5. 통시트(clusters_labelerN)는 ARI 가 필요할 때만 선택 실행

## 5. 본 채점 1차 (2026-09-08\~09, 실수집 9/7 창, 팀 5명 400쌍)

첫 채점이 **묶음 정밀도 0.455·과분리 0.83** 이상값을 검출 → 실수집 잔재의 임베딩
오염으로 진단(티켓 119) → 전처리 수리 후 **같은 400쌍** 재채점: 정밀도 0.658(+20%p).
쌍 라벨 재사용이 설계대로 작동 — 사람 손 없이 설정 비교 가능함을 실증.

남은 신호: 과분리 0.827 = 기계가 사람 기준보다 잘게 쪼갬 (설정 문제).

## 6. 기준값 조정 — 파라미터 스윕 (2026-09-09)

9개 조합(mcs 3·5·8 × nn 15·30·50)을 같은 400쌍으로 자동 채점 (`sweep_cluster_params.py`,
실수집 9/7\~9/8 창 6,620벡터):

| 설정 | 정밀도 | 과분리 | 재현율 | 노이즈 |
|---|---|---|---|---|
| mcs3 · nn15 (기존) | 0.658 | 0.827 | 0.578 | 19.9% |
| **mcs3 · nn50 (채택)** | **0.744** | **0.759** | **0.723** | 24.4% |
| mcs8 · nn50 | 0.654 | 0.892 | 0.775 | 35.0% |

- **채택: umap_neighbors 15→50** — 유일하게 세 지표 동시 개선. 과분리의 지렛대는
  min_cluster_size 가 아니라 UMAP 이웃 수였다(mcs 를 키우면 작은 군집이 노이즈로
  밀려나기만 해 과분리가 오히려 악화 0.827→0.892)
- 비용: 노이즈 +4.5%p — 구제(0.85)·STEP 4 범위. UMAP 시간 소폭 증가(창당 수십 초)
- 주의: 하루치 라벨 한 세트 기준 — 다음 골드셋 창에서 재검증

## 7. 중복 채점 (2026-09-09, 팀 5명 300쌍)

시트는 "고유사(임베딩 ≥0.9)인데 dedup 이 안 접은 쌍" = 놓침 후보만 담았다.
액면 결과(fn 201)는 나빠 보이지만 글자 유사도 진단으로 정체가 갈렸다:

| fn 의 글자(TF-IDF char) 유사도 | 쌍 | 정체 |
|---|---|---|
| 0.95+ (접힘 문턱 이상) | **0** | **파이프라인 스펙 위반 없음** — LSH·검증 놓침 0 |
| 0.85\~0.95 | 15 | 아깝게 문턱 아래(축약판·재게시) — 문턱 실험 후보 |
| 0.85 미만 | 185 (92%) | "같은 정보, 다른 글"(보도자료 재작성) — dedup 정의 밖 |

재작성 쌍의 **94%(189/201)는 이슈 묶음(STEP 3)이 같은 이슈로 흡수** — 계층 설계
검증. 양쪽 다 새는 최종 누수는 후보 300쌍 중 \~12쌍(4%).

**교훈 — 라벨 기준**: 판정 안내("새로 알게 되는 사실이 없으면 O")가 dedup 의 정의
(문장 수준 전재)보다 넓었다. 다음 라벨링부터 중복 O 는 "문장까지 겹치는 전재·
재게시·축약판"으로 한정 (LABEL_GUIDE 반영).
