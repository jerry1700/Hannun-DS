# S15P21E105-121 · DS1 이슈 군집 산출물 DS2 분석 연동

## 목적

DS1이 생성한 실제 이슈 군집 산출물을 읽어 기존 DS2 분석 파이프라인에 연결하고,
BE 연동용 JSONL 결과를 생성한다.

DS1 및 DE 코드는 수정하지 않고 기존 `enrich_issue()` 분석 로직을 사용한다.

## 처리 흐름

DS1 Store 산출물
→ 이슈별 기사 구성
→ DS2 `enrich_issue()`
→ 공통 사실 브리핑 및 기사별 stance 분석
→ BE 전달 형식 변환
→ JSONL 저장

## 구현

실행 스크립트: `scripts/export_ds2_jsonl.py`

주요 기능:
- DS1 실제 이슈 및 기사 산출물 조회
- `structured` 기사 제외
- DS2 입력 스키마 구성
- 기존 `enrich_issue()` 호출
- BE 전달 형식으로 변환
- 날짜별 JSONL 출력
- `--dry-run` 지원
- 동일 날짜 파일 자동 덮어쓰기 방지

## 출력 형식

이슈 1개를 JSONL 1줄로 저장한다.

주요 필드:
- `clusterId`
- `category`
- `factSummary`
- `commonFactsBriefing`
- `clusteredAt`
- `articles[].link`
- `articles[].stance`
- `articles[].viewpointGroupLabel`

`viewpointGroupLabel`은 S15P21E105-120 구현 전이므로 현재 `null`이다.

## 실제 연동 검증

2026-09-07 ~ 2026-09-08 DS1 실제 산출물을 대상으로 실행했다.

- DS1 summary 이슈: 705
- DS2 출력 이슈: 692
- 분석 기사: 5,200
- 분석 대상 기사 없음: 13
- 공통 사실 브리핑 빈 이슈: 246

생성 파일:

`/home/ubuntu/ds_output/2026-09-09.jsonl`

파일은 총 692줄이며 JSONL 전체 형식 검증을 통과했다.

## DS1 원본 교차 검증

출력 결과와 DS1 원본을 다시 비교한 결과:

- unknown_cluster: 0
- factSummary_mismatch: 0
- category_mismatch: 0
- article_links_mismatch: 0
- invalid_stance: 0

따라서 출력된 이슈 ID, 대표 기사 제목, 카테고리, 기사 링크가
실제 DS1 산출물과 일치함을 확인했다.

공통 사실 브리핑이 생성되지 않은 246개 이슈는 임의의 fallback으로
대체하지 않고 현재 DS2 분석 결과 그대로 유지한다.

세부 견해 `viewpointGroupLabel`은 S15P21E105-120 구현 후 반영한다.
